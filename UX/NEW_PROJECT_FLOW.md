# Fluxo de Criação de Projeto

## Objetivo

Permitir que o usuário detalhe profundamente uma ideia antes de iniciar o desenvolvimento.

A criação de um projeto será um processo assistido pelo Solution Architect.

## Etapas

1. Identificação do projeto
2. Problema e objetivo
3. Usuários e processos
4. Escopo inicial
5. Envio de referências
6. Entrevista inteligente
7. Geração do Discovery Report
8. Aprovação humana

## 1. Identificação

O usuário deverá informar:

- Nome do projeto
- Nome curto
- Descrição inicial
- Categoria
- Área de negócio
- Responsável
- Prioridade
- Nível de confidencialidade

## 2. Problema e objetivo

A plataforma deverá perguntar:

- Qual problema será resolvido?
- Como o processo funciona atualmente?
- Quais dificuldades existem hoje?
- Qual resultado é esperado?
- Como o sucesso será medido?

## 3. Usuários e processos

O usuário poderá detalhar:

- Tipos de usuários
- Departamentos envolvidos
- Responsabilidades
- Níveis de acesso
- Processos atuais
- Aprovações necessárias
- Exceções conhecidas

## 4. Escopo inicial

O escopo será separado em:

- Obrigatório
- Desejável
- Futuro
- Fora do escopo

Tipos de solução:

- Sistema Web
- Aplicativo móvel
- API
- Automação
- Integração
- Plataforma SaaS
- Sistema interno
- Outro

## 5. Central de referências

O projeto poderá receber:

- PDF
- DOCX
- XLSX
- CSV
- TXT
- Markdown
- Apresentações
- Imagens
- Wireframes
- Diagramas
- Vídeos
- Áudios
- Links
- Repositórios Git
- Documentação de APIs

Cada referência deverá possuir:

- Título
- Tipo
- Descrição
- Finalidade
- Importância
- Observações
- Origem
- Data de envio
- Versão
- Hash do arquivo

## 6. Entrevista inteligente

O Solution Architect deverá:

1. Analisar todo o contexto disponível.
2. Identificar informações ausentes.
3. Formular perguntas objetivas.
4. Evitar repetir perguntas respondidas.
5. Registrar todas as respostas.
6. Atualizar os requisitos progressivamente.

As respostas poderão ser:

- Texto livre
- Escolha única
- Múltipla escolha
- Número
- Data
- Arquivo
- Confirmação
- Priorização

## 7. Discovery Report

O relatório deverá conter:

- Resumo executivo
- Problema identificado
- Objetivos
- Público usuário
- Processos
- Funcionalidades
- Regras de negócio
- Integrações
- Requisitos não funcionais
- Riscos
- Limitações
- Dúvidas pendentes
- Escopo
- Itens fora do escopo
- Arquitetura inicial sugerida
- Complexidade estimada
- Próximos passos

## 8. Aprovação

O usuário poderá:

- Aprovar o projeto
- Solicitar alterações
- Responder dúvidas
- Adicionar novas referências
- Salvar como rascunho
- Cancelar o projeto

Nenhum desenvolvimento poderá começar sem aprovação humana explícita.

## Estados

- DRAFT
- COLLECTING_CONTEXT
- PROCESSING_REFERENCES
- INTERVIEWING
- GENERATING_DISCOVERY
- WAITING_APPROVAL
- CHANGES_REQUESTED
- APPROVED
- CANCELLED
